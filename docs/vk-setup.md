# Настройка VK Mini App

## Кабинет приложения

Для текущей dev-карточки используйте app ID `54697971`.

1. Пока идёт разработка, оставьте приложение выключенным.
2. После получения публичного HTTPS URL укажите один и тот же URL с `/` для
   мобильной, веб- и desktop-версии.
3. Оставьте привязанным тестовое сообщество Dev Zone (`238552266`).
4. Protected key храните как `VK_APP_SECRET`, service token как
   `VK_SERVICE_TOKEN`, community token как `VK_COMMUNITY_TOKEN` — только на
   backend.
5. Bootstrap admin задаётся числовым VK ID в
   `BOOTSTRAP_ADMIN_VK_IDS`. Дальнейшие роли назначает только superadmin.
6. Включайте приложение и отправляйте на модерацию только после release
   checklist.

Для локального теста внутри VK нужен публичный HTTPS tunnel. Его URL временно
указывается во всех URL-полях карточки. После смены tunnel URL поля нужно
обновить. Browser mock не проверяет VK launch params и не заменяет этот тест.

## Сообщество и уведомления

В сообществе должны быть включены сообщения, а community token должен иметь
право на сообщения. Пользователь отдельно нажимает «Разрешить сообщения»;
серверный `NOTIFICATIONS_ENABLED` остаётся `false`, пока модерация, шаблоны и
лимиты не проверены.

VK notifications также требуют отдельного вызова Bridge и разрешения
пользователя. Наличие токена само по себе не означает разрешение на отправку.

## Перед production

- замените все ключи, которые использовались в dev или передавались в чатах;
- задайте production origin и Secure cookie;
- заполните владельца и контакт в политике конфиденциальности;
- проверьте запуск на iOS/Android VK и vk.com;
- не добавляйте секреты в `VITE_*`, логи, issue или скриншоты.
