# Настройка двух VK Mini Apps

Проект выпускает две независимые frontend-сборки и использует один backend:

| VK-приложение | Сборка | URL | Доступ |
|---|---|---|---|
| Публичное «ИПМКН Старт» | `dist/public` | `https://start.example.ru` | все пользователи |
| Служебное «ИПМКН Старт — управление» | `dist/admin` | `https://admin-start.example.ru` | только редакторы |

Текущую карточку с app ID `54697971` используйте как публичную. В кабинете
разработчика создайте второе Mini App для управления. Не используйте «Режим
разработки» текущей карточки как админскую версию: это только альтернативный URL
для администраторов той же карточки. VK всё равно передаёт тот же `vk_app_id`.

## Публичная карточка

1. В «Настройки → Размещение» укажите `https://start.example.ru/` для мобильного
   приложения, десктопной и мобильной версии сайта.
2. Dev URL используйте только для HTTPS-туннеля публичной сборки на порту 5173.
3. Пройдите модерацию и включите приложение после release checklist.
4. Не добавляйте в эту сборку ссылки на служебный домен.

## Служебная карточка

1. Создайте отдельное VK Mini App с названием «ИПМКН Старт — управление».
2. Для всех платформ укажите `https://admin-start.example.ru/`.
3. Dev URL направляйте на HTTPS-туннель админской сборки на порту 5174.
4. Оставьте приложение доступным только по прямой ссылке и передайте её только
   редакторам. Публикация служебного приложения в каталоге не требуется.
5. Добавьте ответственных разработчиков в раздел «Администраторы» карточки.
   Этот список управляет кабинетом VK, но не заменяет роли внутри проекта.

## Переменные backend

```dotenv
VK_APP_ID=54697971
VK_APP_SECRET=<защищённый ключ публичной карточки>
VK_ADMIN_APP_ID=<id служебной карточки>
VK_ADMIN_APP_SECRET=<защищённый ключ служебной карточки>
BOOTSTRAP_ADMIN_VK_IDS=<числовой VK ID первого администратора>
```

Оба защищённых ключа хранятся только на backend. Не добавляйте их в `VITE_*`,
VK Hosting, frontend-код, логи или Git. ID приложений не являются секретами.

При входе backend:

1. извлекает `vk_app_id` из параметров запуска;
2. выбирает только соответствующий защищённый ключ;
3. проверяет `sign`, `vk_ts`, `vk_user_id` и совпадение app ID;
4. помечает сессию как `public` или `admin`;
5. разрешает `/api/admin/*` только для `admin`-сессии с ролью
   `superadmin`, `content_editor` или `events_editor`.

Поэтому одна лишь прямая ссылка на служебный домен не даёт административных
прав, а роль администратора в публичном приложении также не открывает API.

## Локальная проверка

```bash
pnpm --filter frontend dev
pnpm --filter frontend dev:admin
```

Публичная версия работает на `http://localhost:5173`, служебная — на
`http://localhost:5174`. Browser/dev-вход существует только при
`APP_ENV=development` и `DEV_AUTH_ENABLED=true`; в production маршрут
возвращает 404.

Перед запуском внутри VK создайте два HTTPS-туннеля либо последовательно
проверяйте карточки, меняя их dev URL. Проверяйте iOS/Android VK, vk.ru и m.vk.ru.

## Основание решения

- VK передаёт URL приложения параметры `vk_app_id`, `vk_user_id`, `vk_ts` и
  `sign`; подпись проверяется защищённым ключом на сервере:
  <https://github.com/VKCOM/vk-apps-launch-params>.
- Официальный инструмент VK Hosting принимает один `app_id` на конфигурацию и
  отдельные endpoints для mobile/mvk/web:
  <https://github.com/VKCOM/vk-miniapps-deploy>.
- Актуальный портал разработки и настройки:
  <https://dev.vk.ru/ru/mini-apps/overview>.

## Сообщество и уведомления

К публичному приложению привязано сообщество «Профбюро ИПМКН ТулГУ»
(`78381405`). В сообществе должны быть включены сообщения, а community token
должен иметь право на сообщения. Пользователь отдельно выдаёт разрешение;
наличие токена не означает согласия на уведомления.

Перед production замените ключи, которые использовались в dev или передавались
в чатах, заполните владельца и контакт в политике конфиденциальности и пройдите
`docs/release-checklist.md`.
