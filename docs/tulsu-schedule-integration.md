# Интеграция расписания ТулГУ

Проверено read-only запросами 29 июля 2026 года на официальном
`https://tulsu.ru/schedule/`.

## Наблюдаемый контракт

- `GET /schedule/queries/GetDictionaries.php?term=...` возвращает JSON-массив
  `{value, SORT}`. `SORT=1` — группы, `2` — преподаватели, `3` — аудитории,
  `4` — дисциплины. Endpoint может вернуть большой смешанный список.
- `POST /schedule/queries/GetDates.php`, form `search_value`, возвращает
  `{MIN_DATE, MAX_DATE, SEARCH_FIELD}`. Для группы без расписания даты пустые.
- `GET /schedule/queries/GetSchedule.php` принимает только
  `search_value` и `search_field=GROUP_P`. Официальный frontend читает
  `DATE_Z`, `TIME_Z`, `DISCIP`, `KOW`, `CLASS`, `AUD`, `PREP`, `GROUPS`.
- `GET /schedule/queries/GetCalendar.php?search_value=...` возвращает периоды
  с `BEGIN_DATE`, `END_DATE`, `VID`; пустой массив является допустимым ответом.

Официальной гарантии стабильности и опубликованного rate limit не найдено.
Поэтому браузер не обращается к endpoints напрямую: backend разрешает только
четыре перечисленных пути, ставит таймаут, делает один ограниченный повтор
безопасного GET и кэширует нормализованный ответ.

Словарь `GetDictionaries.php` не является полным перечнем допустимых групп и не
используется как белый список. Пользователь может сохранить любой номер формата
`123456` или `123456-78`; расписание для него запрашивается напрямую через
`GetSchedule.php`. Таблица `student_groups` хранит закладки и связи с тьюторами,
а не ограничивает доступные номера.

## Отказоустойчивость

Свежий кэш отдаётся без внешнего запроса. При ошибке ТулГУ последний успешный
ответ возвращается с `is_stale=true` и исходным временем обновления. Если кэша
нет, API отвечает `503` без технических деталей. Пустое расписание сохраняется
как успешный ответ, а не как ошибка.

Счётчик до сессии не показывается, пока календарь не вернул валидный период.
Произвольный proxy URL отсутствует.
